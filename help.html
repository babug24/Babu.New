NVDA Test Automation - Help

Automated accessibility testing tool that drives NVDA (NonVisual Desktop Access) and a Chromium browser to verify page content, headings, landmarks, focusable elements, images, ARIA labels, form controls and dynamic content across a list of URLs.

Contents: Overview Requirements Setup urls.csv Format Running Tests What Gets Tested Configuration Reports & Output Troubleshooting

Overview

This tool reads a list of page URLs from urls.csv, opens each page in a visible Chromium browser via Playwright, starts NVDA, and runs a series of accessibility checks (content, headings, landmarks, focus order, images/alt text, ARIA labels, forms, dynamic content). Results are collected and exported as HTML and Excel reports, with screenshots captured for each page.

Requirements

  • OS: Windows (NVDA is a Windows-only screen reader)
  • NVDA installed and available on the system
  • Node.js (with npm)
  • Project dependencies installed (see Setup below)

Setup

cd nvda-test-automation
npm install

This installs: @guidepup/guidepup (NVDA driver), playwright (browser automation), fs-extra, csv-parser, xlsx, chalk, ora.

Playwright may require its browser binaries. If Chromium isn't already installed, run npx playwright install chromium.

urls.csv Format

Create/edit urls.csv in the project root with a header row containing a URL column. Accepted header names (case-insensitive): url, website, link, page, or website url.

url
https://example.com/page-one/
https://example.com/page-two/
www.example.com/page-three/

URLs without a protocol are automatically prefixed with https://. Invalid URLs are skipped with a warning, not a failure.

Running Tests

npm test

or directly:

node nvda-test-automation.js

The Chromium browser opens visibly for each page (headless mode is true for NVDA/Playwright internals but the visibility config forces the browser window to be shown). If debug.enabled is true in the config, the script pauses after each page and waits for you to press Enter before continuing to the next URL.

What Gets Tested (per page)

TestPurpose
Content ReadingConfirms the page has meaningful text content (>100 characters) and a title.
Heading NavigationVerifies headings (h1-h6, role="heading") exist and form a sensible structure.
Landmark NavigationChecks for ARIA/HTML landmarks (header, nav, main, footer, etc.).
Focusable ElementsValidates interactive elements (links, buttons, inputs) can receive keyboard focus.
ImagesDetects broken images and checks for missing/empty alt text, skipping known decorative/tracking patterns.
ARIA LabelsConfirms interactive elements have accessible names via ARIA attributes.
Form ControlsChecks form inputs have associated labels.
Dynamic ContentChecks for live regions / dynamically updated content handling.

A page is marked PASS only if all of its tests pass; otherwise it is marked FAIL.

Configuration

All settings live in the CONFIG object at the top of nvda-test-automation.js:

KeyDescription
csvPathPath to the input CSV file (default ./urls.csv)
reportsDirBase folder for generated reports/screenshots (default ./reports)
timeout / navigationTimeout / speechTimeout / nvdaStartTimeoutTimeouts (ms) for various operations
retryAttemptsNumber of retries for a failed page test
visibility.*Controls forcing the browser/page to be visible, waiting for render/images, and taking screenshots
stealth.*Anti-bot-detection options: realistic user agent, randomized viewport, human-like delays/mouse movement, cookie acceptance
images.decorativePatterns / images.skipPatternsFilename patterns to treat as decorative or skip entirely during image checks
debug.enabled / debug.pauseOnFinishPause and keep the browser open after each test until Enter is pressed

Reports & Output

After a run, results are written under reports/:

  • reports/html/test-report-<timestamp>.html - human-readable HTML report with pass/fail summary per page and per test
  • reports/excel/ - Excel (.xlsx) export of the same results for spreadsheet analysis
  • reports/screenshots/ - screenshot captured for each tested page

Console output also shows a live summary (pages found, invalid URLs skipped, pass/fail per test) using colorized output.

Troubleshooting

  • "No URLs found in CSV": Ensure urls.csv exists and has a url (or accepted alias) header column with at least one row.
  • Browser doesn't appear: Confirm visibility.showBrowser / forceVisible are true in CONFIG.
  • NVDA doesn't start: Make sure NVDA is installed and not already blocked by another running instance; increase nvdaStartTimeout if needed.
  • Script seems to hang between pages: This is expected if debug.enabled is true — press Enter in the terminal to continue.
  • Invalid URLs skipped: Check the console warning list; fix or remove entries in urls.csv.
